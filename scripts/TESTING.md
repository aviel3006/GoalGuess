# בדיקות אבטחה וזרימה

שני תסריטים שבודקים את השרת (Supabase) של GoalGuess לפני עלייה לחנות. שניהם
פותחים משתמשי בדיקה זמניים ומוחקים אותם בסוף.

## לפני ההרצה: מפתח השירות

הבדיקות צריכות את מפתח השירות (service_role) של הפרויקט. **אסור לשמור אותו
בקובץ ואסור להעלות אותו ל-git** — מדביקים אותו למשתנה סביבה להרצה אחת בלבד.

היכן למצוא אותו: בלוח הבקרה של Supabase →
`Project Settings` → `API` → `Project API keys` → המפתח `service_role (secret)`.

## הרצה

ב-PowerShell (ווינדוס):

```powershell
$env:SUPABASE_SERVICE_ROLE_KEY = "<המפתח>"
npm run audit:security   # בדיקות אבטחה
npm run test:flow        # בדיקות זרימה
```

כשסוגרים את חלון ה-PowerShell המשתנה נמחק מעצמו.

## מה כל תסריט בודק

### `npm run audit:security` — בדיקות אבטחה

פותח שני משתמשים: A (התוקף) ו-B (הקורבן), ומנסה כ-A לפרוץ להגנות. כל שורת
`PASS` פירושה שהשרת חסם את הפעולה כמו שצריך; `FAIL` פירושו שחור באבטחה.

1. קריאה ושינוי של ניחושים של משתמש אחר (RLS).
2. קריאה של טבלאות פנימיות (שמות משתמש, דיווחים, רשימת המילים האסורות).
3. שינוי/מחיקה של ליגה של משתמש אחר, והצטרפות לליגה בלי קוד.
4. זיוף חסימה בשם משתמש אחר.
5. מסנן המילים בשם משתמש ובשם ליגה.
6. העלאת קובץ לתיקייה של משתמש אחר באחסון.
7. הסתרת שחקן חסום בטבלת הדירוג.

התסריט יוצא עם קוד שגיאה אם משהו נכשל, כך שאפשר להריץ אותו גם במערכת אוטומטית.

### `npm run test:flow` — בדיקות זרימה

מריץ את המסע של משתמש אמיתי עם המפתח הציבורי בלבד (כמו האפליקציה המותקנת):
הרשמה, בחירת שם משתמש, טעינת משחקים, שמירת ניחוש (אם יש מחזור פתוח), פתיחת
ליגה, הצטרפות של משתמש שני עם קוד הזמנה, וטעינת טבלאות הדירוג. מדווח על כל
שלב שנכשל.

> הערה: בדיקת הזרימה יכולה לרוץ גם בלי מפתח השירות, אבל אז המשתמשים הזמניים
> לא יימחקו אוטומטית בסוף ויצטרכו מחיקה ידנית.
